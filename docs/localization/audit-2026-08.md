# PDF Toolkit — Localization Audit Report

Audit mode: **read-only** (no files modified). Scope: `app/src/main/res/values*/strings.xml` (15 locales) + Compose UI in `app/src/main/java`.

---

## A. MISSING KEYS

**Resource-level result: no missing keys.** All 15 locale files define all 285 default keys; zero missing, zero empty. The English fallback problem is **not** caused by missing keys in the locale files — it is caused by hardcoded English string literals in Compose that never reference resources at all (so they render English in **every** locale, not as a fallback).

### A2. Dead translated resources (the inverse problem)

124 of the 285 default keys are **never referenced** in any `.kt` file — the translations exist in all 15 languages but the UI never consumes them. Notably: all `compress_*` (13), `split_*` (11), most `pdf_*` (25), `label_*` (10), `error_*` (9), `theme_*` (6), `image_format_*` (4), `file_picker_*` (4), `feature_request_category_*` (4), `language_*` (6), `bug_report_*` (2), and 14 `action_*` keys. E.g. `CompressScreen`, `SplitScreen`, `PdfViewerScreen`, `MetadataScreen` hardcode English while their fully-translated `compress_*`/`split_*`/`pdf_*` resources sit unused.

**Screens needing the most attention (locale-independent):** PdfViewerScreen (50 hardcoded literals), MetadataScreen (23), ScanToPdfScreen (19), AnnotationScreen (18), **History sidebar (10, confirmed never localized)**, FilesScreen recent-files cluster (6) — all render English in every locale because they bypass resources entirely.

**Locales needing the most attention:** `ru` (highest generic/literal load, plus brand translation in the footer), `fr` and `ja` (broken MT + `amp;` leaks), `tr` (infinitive verb forms). **Top 3 priorities before planning fixes:** (1) wire hardcoded literals to the existing 124 dead resource keys and add keys for the History cluster; (2) fix the `view_pdf` card wrong-key at ToolsScreen.kt:544; (3) repair `desc_convert_format` corruption and `amp;` leaks in default + fr/ru.
